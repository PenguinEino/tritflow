## 横断する決まり

- 見た目は1つの様式にそろえる（`notebook/style.py`）。論文の図（`figures/paperstyle.py`）と同じ明朝系の書体・墨色・三値の色（−1青、0灰、+1赤）・強調色1つ。表は罫線3本（上・見出しの下・下）で縦線なし。ボタンとスライダーは細い罫線と墨色だけ。図はすべて白地。進捗の行（`live.step`）だけはログなので等幅のまま。回路図は1つの図に1種類（トランジスタ回路はXschem、ゲート回路はTritFlowの描画）。
- 本文は専門用語をそのまま使う（配置配線、論理合成、抽出、ポストレイアウトシミュレーション）。平易な言い換えや比喩、ポエム調の文は書かない。
- ログや図を見れば分かること（セル数、合格など）は本文に書かない。本文は図やログで分からないこと（条件、判定の基準、制約）だけ。
- 説明していない概念を突然出さない（例：クリーネ）。
- HDLは独立したセルに置く。
- 本文の数字は、セルの出力として見せる。生成器と数値の差し込みは使わない。
- 各章のassertと証拠表はノートブックから外し、テスト（ノートブックを実行するpytest）に移す。ノートブックには付録の検証セル1つだけを置く。
- 日本語版を確定させてから、英語版を同じセル構成で作る。

### セル内のログ

- 最近のCLIツールのように、シンプルで分かりやすく、格好よく。
- 実行中は1行を書き換え続ける：スピナー、作業の概要、実際の進捗、経過時間。終わったら `✓ 概要  結果の一言  経過時間` で確定し、次の作業の行へ進む。時間の予測は出さない。
- 実行順の誤りでは、トレースバックより先に、目立つ枠で「先に何を実行するか」と「なぜダメか」を出す。トレースバックはその下に出してよい。

### ログの実装（試作済み、2026-10-20）

- `tritflow/progress.py`：配置（焼きなましのステップ、配線長、セルの位置）と配線（ネットごとの線分）のイベント。聞き手がいなければ何もせず、結果は変わらない。フックは `pnr/placement.py` と `pnr/router.py` だけ。これらは記録済み4回路の入力なので、リリース前に取り直す（約6分）。
- `notebook/live.py`：`with step("配置配線", view=LayoutView()) as s:` で、裏のスレッドが0.1秒ごとに行を書き換える。KLayoutは `-d 11` で処理ごとのログを出させ、ngspiceは「Reference value」（シミュレーション時刻）を、どちらも実行中に読む。`sim/runner.py`、`pnr/verify.py`、`extract/lvs.py` は寸法の掃引・セル検証・サインオフの鮮度判定に使われているので触らない。
- 順番の誤り：`need("net", why=...)` と、未定義の変数（NameError）を作るセルの登録 `provides()` で、枠を出す。
- Colabでの確認（CLI、新しいVM、`notebook/v2/prototype_live.ipynb`）：裏のスレッドからの表示更新は届く。全ステップが動き、順番の誤りの枠も出た。
- 見つかった課題：
  - ngspiceの出力がまとめて届くため、シミュレーション時刻が飛び飛びになる（1.77 µsのあと4.80 µs）。出力のバッファを切る（`stdbuf` か擬似端末）。
  - KLayoutの起動から最初のログまで約3秒、何も出ない。起動中であることを表示する。
  - 配置配線の中でも、配線のあとにKLayoutのDRCが走る。その間の表示を配置配線の段階として分かるようにする。
  - 実況の図は、四角と線では抽象的すぎた（著者）。実際のセルGDSと実際の幅の配線を、TR-1um.lypの色とKLayout風の模様で描くように変えた。著者がColabで見て「良い感じ」。そのあと「黒背景はVNCのようで動いている感じがしない」で白背景と枠にし、直前に配線したネットをオレンジで光らせた（2026-10-20）。2トリット加算器で1コマ約1 MBなので、図の更新は0.6秒おき。

## 普通のVerilogとALU（2026-10-20決定）

- TritVerilogは信号の算術・比較・`case`・`?:`・`always @(*)`が書けなかった（`+`はエラー）。HDL_VERILOGストリーム（`~/code-a-chip-hdl`、ブランチ `hdl-verilog`、`briefs/HDL_VERILOG.md`）で、学校で習う組合せ回路のVerilogを一通り書けるようにし、NANYと±1の定数の完全性を使って任意の組合せ回路を合成できるようにする。真偽はKleeneの三値論理（真＝+1、不明＝0、偽＝−1）。
- 順序回路は今回は見送る（ラッチ・合成・状態のある検証・STAまで要り、著者が把握しきれない）。8章の今後の計画に書く。
- 本文での使い方：
  - 4章：全加算器を `assign {cout, sum} = a + b + cin;` の1行で書き、手で並べた版とセル数を並べる。
  - 7章：`case`、`+`、`-`、`?:` で書いた小さな三値ALU（命令トリットで加算・減算・符号反転・min・max）を主役にし、合成→配置配線→DRC/LVS→全命令のSPICEまで。読者はこれを書き換えて自分の回路を作る。
  - 8章：このALUをMPWフレーム付きのフルチップにし、次のOpenSUSIシャトルに出す候補として提出用一式を作る。
  - 冒頭：「HDLを書き換えれば」を、普通のVerilogで書いたALUがそのままGDSになる、という具体的な一文に強める。
- ALUの命令セットと桁数（2か3トリット）は、ストリームの結果とColabでの実行時間を見て決める。
