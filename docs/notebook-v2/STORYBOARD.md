# ノートブック v2 の骨格

2026-10-20、著者と相談して決めた方針。フロー本体はほぼ完成したので、ノートブックは一から作り直す。骨格を先に決め、0章（冒頭）と最終章から作り、各章をColabで動かして見てもらいながら進める。

## 主題と語り口

- 主題：三値のHDLが、製造できるGDS（DRC/LVS済み）になる。自分で書き換えられる。
- 語り口：設計ツールの紹介。主張は「新しいオープンな三値の設計フローと、テープアウトできるライブラリ」で、教育は従。
- 流れ：全体→部品→組立て。最初に素朴な回路を一気にGDSまで通し、そのあと中を開ける。
- 呼び方：「オープンソースPDK」。初出だけ「日本で初めて商用ファブが公開したオープンソースPDK」。「NDA不要の公開PDK」は繰り返さない。

## 冒頭

順番：

1. つかみ：3値は今も使われている（GDDR7（JEDEC JESD239、2024年）とUSB4 Version 2.0（2022年）のPAM3、重みが{−1, 0, +1}のLLM BitNet b1.58（2024年））。TritFlowはこれらの回路そのものではないので、つかみとしてだけ使う。
2. 空白：三値論理の研究は新しいデバイスやシミュレーションの上にあり、合成もゲートネットリストまで（GT-LOGIC, IEEE Access 2025）。オープンなツールはCMOS向けには三値を二値に変換する（MRCS）。製造できるオープンソースPDKでGDSまで通す道は、探した範囲では見当たらない。「初の」とは書かない。
3. TritFlow：TR-1umで、テープアウトした三値セルから、HDL→GDS→DRC/LVS→抽出後SPICEまで通す。書き換えれば自分の回路でも同じことができる。
4. 場の意義（冒頭では1文、詳しくは8章）：TR-1umは日本で初めて商用ファブが公開したオープンソースPDK。そこで型破りな回路を実際のテープアウトと組み合わせて実証することは、オープンソース半導体のプロセスの選択肢を増やし、日本のオープンソース半導体の芽吹きになる。
5. 実証と価値：①設計（済み、このノートブックで誰でも再現）②シリコン（2027年1月にチップ到着、採択されたらISSCC 2月14〜18日のポスターで実測と予測を並べる）③再利用（TritFlowの加算器を次のOpenSUSIシャトルに出す予定）。日本の新しいオープンソースPDKが、標準外の回路でも設計→製造→実測を一巡できると世界に示す最初の例になる。お願い調にせず「この実証が何を可能にするか」として書く。
6. Code-a-Chipの3つの価値：再利用・再現・教育を、どう実現しどの章で体験できるかの表。教育の行は「デジタルなのにアナログ的な調整が要る部分が少しあり、学ぶ題材として悪くない」程度。これは「なぜ三値か」ではなく教育の説明として書く。
7. 図1（著者とやり取りしながら作る）、そして「すべてのセルを実行」。冒頭は1画面に収め、最初に手を動かすまでを短くする。

### 1章

- 表示・案内するのは入力の選択だけ。ただし読者が好奇心で `a & ~a` を書き換えても最後まで動くように作る。
- 最後に「いま何が起きたか」の地図：フローの各段を1枚の図にし、TritFlowが作った部分（三値HDLの読込み、合成、セル生成、配置配線、配線容量の見積もり、三値テストベンチと±0.5 Vの帯での判定、三値STA）と、既存の道具（PDKのKLayoutデッキ、KLayoutの素子抽出、ngspice＋PDKモデル）を色で分ける。

### 2・3章

- 2章はINVだけに絞り、じっくり触れるようにする。xschemの書き出しは大きく冗長なので、回路図は小さく描き直す。元の回路図は折りたたみ。
- 3章で完全性、採用した部品とその理由、スタンダードセルにする作法（P&Rで使えるようにする）を説明する。完全なのはセルの組で、フローではない（合成は式を写すだけで、真理値表から任意の関数を合成しない）。セル数を「最小」と書かない。

### 5・6章

- 各章の頭に「TritFlowはこうやっている」を短く置く（3〜4行と小さな図。アルゴリズム）。そのあとに実例。
- 5章の頭には、なぜ自作したかを2〜3文で書く。アルゴリズムの説明とは別の文にする。
  > 配置配線は信号が2値か3値かを問わないので、原理的には OpenROAD も使えます。TR-1um でも LibreLane への移植が試みられています（luyanaa/TR-1um、実験段階）。ただ、TR-1um で配線に使えるメタルは2層だけで、三値のセルは Liberty で表せず、全セルに3本の電源レールを通す必要もあります。そこで TritFlow は、セル行の間にチャネルを空けて2層で配線する、小さな配置配線器を持っています。
  - 「2層だからOpenROADでは無理」とは書かない。
- 配置配線は読者のColabで実際に実行する（録画は使わない）。実行中は図を更新し続ける実況と、ログ行の進捗。終わったら、その実行の途中経過をスライダーで振り返れる。
- 配線容量あり／なしの比較は常識なので本編では1文だけ。桁数の掃引と静的電力のまとめはなくす。

### 8章

- 最後のセルで `to_chip()` と `signoff()` により、読者の回路（または加算器）をその場でフレーム（`OSS_FRAME_TEG`、2.5 mm角）付きのフルチップにし、描画DRC、LVS、MDP後のマスクDRC、MPWの事前チェックを通す。ローカルでは `a & ~a` で配置配線1.0 s、チップ化4.1 s、サインオフ3.8 s、全チェック合格。
- GDSビューアで見せ、テンプレートの形式（`tr_1um_<名前>.gds`、`.cir`、`info.yaml`）の一式をzipでダウンロードできるようにする。
- 事前チェックは公式の `OpenSUSI/TR-1um_MPW_template` をコミットで固定して取得する（今は手元のフォーク `TR-1um_MPW_Sanken`）。
- 本文では「提出できる形式で、チェックをすべて通ったGDS」と言う。実際の提出に残る作業（領域の割当、パッドとボンディング、ESDや電源の承認、受動パッドにESDなし）は付録に1文。
- チップ（1トリットのMAC、81入力、出力Sum・Cout・AND・OR。ANDとORはNAND→INV、NOR→INVの出力でゲートに近い動作も測れる。TritFlowのレイアウトは載っていない）の測定計画は文章で書く。MACの予測表は作らない。
- 今後：セルをLEFで書き出し、OpenROAD系のフローでも配置配線できるようにする（両対応）。

### ログの実装（試作済み、2026-10-20）

- `tritflow/progress.py`：配置（焼きなましのステップ、配線長、セルの位置）と配線（ネットごとの線分）のイベント。聞き手がいなければ何もせず、結果は変わらない。フックは `pnr/placement.py` と `pnr/router.py` だけ。これらは記録済み4回路の入力なので、リリース前に取り直す（約6分）。
- `notebook/live.py`：`with step("配置配線", view=LayoutView()) as s:` で、裏のスレッドが0.1秒ごとに行を書き換える。KLayoutは `-d 11` で処理ごとのログを出させ、ngspiceは「Reference value」（シミュレーション時刻）を、どちらも実行中に読む。`sim/runner.py`、`pnr/verify.py`、`extract/lvs.py` は寸法の掃引・セル検証・サインオフの鮮度判定に使われているので触らない。
- 順番の誤り：`need("net", why=...)` と、未定義の変数（NameError）を作るセルの登録 `provides()` で、枠を出す。
- Colabでの確認（CLI、新しいVM、`notebook/v2/prototype_live.ipynb`）：裏のスレッドからの表示更新は届く。全ステップが動き、順番の誤りの枠も出た。
- 見つかった課題：
  - ngspiceの出力がまとめて届くため、シミュレーション時刻が飛び飛びになる（1.77 µsのあと4.80 µs）。出力のバッファを切る（`stdbuf` か擬似端末）。
  - KLayoutの起動から最初のログまで約3秒、何も出ない。起動中であることを表示する。
  - 配置配線の中でも、配線のあとにKLayoutのDRCが走る。その間の表示を配置配線の段階として分かるようにする。
  - 実況の図は、四角と線では抽象的すぎた（著者）。実際のセルGDSと実際の幅の配線を、TR-1um.lypの色とKLayout風の模様で描くように変えた。著者がColabで見て「良い感じ」。そのあと「黒背景はVNCのようで動いている感じがしない」で白背景と枠にし、直前に配線したネットをオレンジで光らせた（2026-10-20）。2トリット加算器で1コマ約1 MBなので、図の更新は0.6秒おき。

## 普通のVerilogとALU（2026-10-20決定）

- TritVerilogは信号の算術・比較・`case`・`?:`・`always @(*)`が書けなかった（`+`はエラー）。HDL_VERILOGストリーム（`~/code-a-chip-hdl`、ブランチ `hdl-verilog`、`briefs/HDL_VERILOG.md`）で、学校で習う組合せ回路のVerilogを一通り書けるようにし、NANYと±1の定数の完全性を使って任意の組合せ回路を合成できるようにする。真偽はKleeneの三値論理（真＝+1、不明＝0、偽＝−1）。
- 順序回路は今回は見送る（ラッチ・合成・状態のある検証・STAまで要り、著者が把握しきれない）。8章の今後の計画に書く。
- 本文での使い方：
  - 4章：全加算器を `assign {cout, sum} = a + b + cin;` の1行で書き、手で並べた版とセル数を並べる。
  - 7章：`case`、`+`、`-`、`?:` で書いた小さな三値ALU（命令トリットで加算・減算・符号反転・min・max）を主役にし、合成→配置配線→DRC/LVS→全命令のSPICEまで。読者はこれを書き換えて自分の回路を作る。
  - 8章：このALUをMPWフレーム付きのフルチップにし、次のOpenSUSIシャトルに出す候補として提出用一式を作る。
  - 冒頭：「HDLを書き換えれば」を、普通のVerilogで書いたALUがそのままGDSになる、という具体的な一文に強める。
- ALUの命令セットと桁数（2か3トリット）は、ストリームの結果とColabでの実行時間を見て決める。
